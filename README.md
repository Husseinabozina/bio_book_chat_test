# bio_book_chat_test — مختبر هندسة تحويل PDF العربي إلى Word

## قرارات هندسية ملزمة قبل تسليم أي Word (2026-10-16)

القرارات الثمانية عشر المبنية على أخطاء التجارب: [ENGINEERING_DECISIONS.md](docs/ENGINEERING_DECISIONS.md). تم تنفيذ بوابة صارمة تفصل بين *نجاح التحويل* و*اعتماد النتيجة*. كلمة "ناجح" في CI تعني نجاح اختبارات البرنامج فقط.

**أداة منع التسليم الخاطئ:**

```sh
# بعد تنفيذ أي DOCX وبعد إعداد ملف أدلة مراجعة خاص، غير مرفوع للريبو العام:
bio2word release-check outputs/candidate.docx runs/private_evidence.json \
  --render --report runs/release.json
# exit 3 -> BLOCKED; exit 0 -> مؤهل للمراجعة النهائية فقط، وليس موافقة المستخدم
```

نموذج البيانات: [RELEASE_EVIDENCE_TEMPLATE.json](docs/RELEASE_EVIDENCE_TEMPLATE.json) **غير معتمد عمدًا** ولا ينجح بتعبئته بقيم افتراضية. بوابة الإصدار تفحص أن نص Word قابل للتعديل، وكل عنصر له إثبات مراجعة المصدر وإحداثياته المقاسة بعد العرض، واتجاه RTL/LTR، ومعايرة الخط، وسلامة OOXML، ونسخة Word التي فُتح عليها *نفس الملف* مع رقم بصمته. الادعاءات المكتوبة في JSON لا تثبت بحد ذاتها صدق المراجعة؛ يلزم دليل فعلي واعتماد إنساني.

**ما لم ينفذ بعد:** محرك معايرة الخط التلقائي، واستنتاج فقرات وأعمدة الكتاب، واستخراج إحداثيات الناتج تلقائيًا، واختبار Word Desktop بدون مساعدة المستخدم. لذلك تجاربنا القديمة **ما زالت غير معتمدة**. انظر [معايير الجودة](docs/QUALITY_GATES.md).


المشروع **نظام تجريبي قابل للتكرار والقياس** لتحويل الكتب العربية العلمية من PDF إلى DOCX، ومعرفة *لماذا* يفشل التحويل، بدل إنتاج ملف يبدو أنه تم بنجاح لكن يحتوي أخطاء إملائية واتجاهات وتنسيق.

> الحالة الحالية: **v0.1 / research prototype**. مسار `visual` يحافظ على شكل صفحات PDF عبر إدراج صورة لكل صفحة **لكنه غير قابل لتعديل النص**. مسار `editable` يكتب نص Word حقيقيًا ويحتفظ بمقاطع الصور النقطية، لكن إعادة بناء الجداول والأعمدة والرسومات المتجهية غير مكتملة. `hybrid` يمنع تمرير النص المتضرر بصمت، ويستخدم الصفحة كصورة عند فشل سلامة استخراج النص. لا يُدّعى تطابق بصري أو لغوي تلقائي.

## البداية السريعة

```bash
python -m venv .venv
source .venv/bin/activate    # Windows: .venv\\Scripts\\activate
pip install -e '.[dev]'

# الملف الأصلي يظل محليًا، لا ترفعه للريبو العام
bio2word inspect input/book.pdf --pages 7,8,10,14,16 --report runs/preflight.json

# وثيقة صور مطابقة بصريًا تقريبًا لكن النص غير قابل للتحرير
bio2word convert input/book.pdf outputs/visual.docx --pages 7,8,10,14,16 --mode visual

# أفضل مسار أمان حاليًا: لا ينسخ المحارف الفاسدة بصمت
bio2word convert input/book.pdf outputs/hybrid.docx --pages 7,8,10,14,16 --mode hybrid --report runs/conversion.json

# تحويل قابل للتعديل، يرفض الصفحات ذات Unicode التالف افتراضيًا
bio2word convert input/book.pdf outputs/editable.docx --pages 7,8,10 --mode editable

# تجاوز البوابة للتجارب فقط، وقد يخرج نصًا معطوبًا
bio2word convert input/book.pdf outputs/unsafe.docx --pages 7,8,10 --mode editable --allow-suspect-text

# فحص بنية Word وإعادة عرض اختياري (يتطلب LibreOffice)
bio2word audit outputs/hybrid.docx --source input/book.pdf --pages 7,8,10,14,16 --render --report runs/audit.json
pytest -q
```

استخدم `python -m bio_book_chat_test ...` إذا لم يتوفر الأمر بعد التثبيت.

## مسارات التحويل الحالية

| المسار | النص قابل للتعديل؟ | مطابقة التصميم؟ | القرار الصحيح |
| --- | --- | --- | --- |
| `visual` | لا | مرتفعة نظريًا، تُراجع بعد العرض | مرجع بصري / طباعة |
| `editable` | نعم (النص المستخرج) | **تقريبية** | فقط بعد نجاح سلامة النص والمراجعة |
| `hybrid` | في الصفحات السليمة فقط | تختلف حسب الصفحة | الافتراضي الآمن أثناء التطوير |

**لا تستخدم `hybrid` إذا كان مطلوبًا أن تكون جميع الصفحات قابلة للتعديل.** يجب أولًا معالجة الخطوط أو الاستعانة باستخراج بصري/مراجعة بشرية مع تسجيل نتيجة كل صفحة.

## ماذا يفعل المشروع؟

1. **Preflight:** يفحص أبعاد صفحات PDF والخطوط، وعدد المقاطع والصور، والمحارف المشبوهة مثل `U+FFFD` ومحارف التحكم الناتجة عن ترميزات قديمة.
2. **Classification:** يحدد صفحات يُمنع استخراجها تلقائيًا دون مراجعة بشرية.
3. **Conversion strategies:** يختار وضعًا صريحًا، ولا يقدم الصور باعتبارها Word قابلًا للتعديل.
4. **RTL/BiDi:** يضبط `w:bidi` للفقرة و`w:rtl` للمقاطع بحسب النص؛ لا يعكس السلاسل النصية يدويًا.
5. **QA:** يفحص أجزاء Word والبنية العربية ويعيد عرض المستند اختيارياً لقياس عدد الصفحات.
6. **Traceability:** تقارير JSON لكل تشغيل، يمكن الاحتفاظ بها خارج Git لمقارنة التجارب.
